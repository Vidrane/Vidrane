# Vidrane — план разработки

Дата базовой ревизии: 2026-11-24. Основание: `main` на `fe1df8b33ecec237274b109e4a031684f6894c65`, документация репозитория и запись nPlayer Plus `ScreenRecording_11-23-2026 01-58-03_1.mp4` (14:47).

## Цель, границы и принципы

1. Бесплатный, open-source плеер без Free/Lite/Plus, подписок и ограничений функций. Personal / Developer — **профили подписи iOS**, не редакции продукта.
2. На iOS достичь функционального покрытия показанного в nPlayer Plus, затем развивать самостоятельный, удобный интерфейс Vidrane. Не копировать код, иконки, ассеты и фирменные элементы nPlayer.
3. Rust — общее ядро (модели, политики, парсеры, очереди, адаптеры где это разумно), нативный интерфейс SwiftUI на iOS, архитектура для Android/Windows/Linux/macOS.
4. В **обе** основные IPA входят AVFoundation и libmpv/FFmpeg. Vidrane Player — основной интерфейс; Apple Player — дополнительный. Системные API и libmpv не следует выдавать за взаимозаменяемые при отсутствии возможностей.
5. Не заявлять поддержку кодека, протокола, DRM, pass-through или фонового режима, пока не проверены путь кода, доступность на платформе и тесты.
6. Реальные испытания на iPhone отложены по решению пользователя до широкого покрытия функций. До этого обязательны CI, unit/integration/mock tests, статические проверки. Итоговое качество на устройстве помечается «не проверено».
7. Соблюдать безопасность подключений: TLS, проверка ключа SSH, безопасные корни удалённых файлов, Keychain, блокировка SSRF/опасных редиректов, защищённый localhost relay. Legacy-режимы без защиты не включать тихо.
8. До публичного распространения пройти аудит лицензий и кодеков (MIT + LGPL/GPL FFmpeg/libmpv/libsmb2 и другие зависимости), уведомлений и способов перелинковки.

## Условные статусы

- `CODE` — базовая функция уже реализована в исходниках, но без реальных испытаний.
- `PARTIAL` — неполный сценарий по сравнению с nPlayer.
- `TODO` — отсутствует; задача в плане.
- `BLOCKED` — зависит от Apple API, entitlement, внешнего API или технической проверки.
- `VERIFIED` — подтверждено тестами/реальным устройством. Пока этот статус не присваивается без соответствующего подтверждения.

Полную матрицу смотреть в [NPLAYER_PARITY.md](NPLAYER_PARITY.md). Ниже — **план**, а не утверждение о готовности.

## Базовая реализация на 2026-11-24

`CODE`: Rust core/FFI; SwiftUI вкладки «Локально», «Сеть», «Плейлисты», «Браузер», «Загрузки», «Настройки»; локальные CRUD файлов/папок и история; AVFoundation и libmpv в обеих unsigned IPA; SRT/VTT; WebDAV HTTPS; SFTP с pinning; зашифрованный SMB3; byte-range relay для libmpv; сохраняемая очередь загрузок HTTPS/WebDAV/SFTP/SMB; Rust CI и iOS unsigned build. Эти возможности требуют тестов совместимости/нагрузки/устройства.

## Приоритеты и порядок работы

- **P0** — корректность, безопасность, путь к nPlayer parity, сборка и тесты. Без этого нельзя считать этап завершённым.
- **P1** — важные функции nPlayer, не блокирующие каждый следующий этап; выполняются в соответствующем модуле.
- **P2** — опциональные интеграции/эффекты и функции, требующие специальных лицензий или ограниченных системных API; реализуются после feasibility review, без ложных обещаний.
- Один активный этап из последовательности M00–M13. Параллельное исправление критических ошибок допускается. Большие задачи разбивать на завершённые вертикальные проходы (ядро → UI → тесты → документация), а не переписывать весь проект сразу.
- После каждого прохода: коммит(ы), ссылка на diff, CI, краткий список завершённого, непройденного и точный следующий ID. Не объявлять выполнение без проверки состояния `main`.
